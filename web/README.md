# Web dashboard

Live at **<https://predict-brasileirao.vercel.app>**.

Static Next.js site (App Router, TypeScript, Tailwind, Recharts) that shows the predictions in Portuguese and English.
Everything is precomputed by Python; the site only reads JSON files, and the **What if…?** page re-runs the
Monte Carlo simulation in the browser (`src/lib/simulator.ts`, a port of `src/brasileirao/simulate.py`).

## Run locally

```bash
cd web
npm install
npm run dev        # http://localhost:3000 (redirects to /pt/ or /en/)
npm test           # simulator tests, incl. parity with the Python results
npm run lint
npm run build      # static site in web/out/
```

To refresh the data first (from the repo root, in the `brasileirao` conda env):

```bash
python -m brasileirao.export --refresh
```

## Pages

| Route | What it shows |
|---|---|
| `/[lang]/` | standings + title / top-6 / relegation chances, model selector |
| `/[lang]/models/` | the three models side by side, next games, team strengths |
| `/[lang]/history/` | weekly snapshots of each team's chances over the season |
| `/[lang]/what-if/` | pick results, see the chances change (simulated in the browser) |
| `/[lang]/accuracy/` | backtest leaderboard and calibration chart |
| `/[lang]/how-it-works/` | plain-language explanation |

## Data contract (`public/data/`, written by `python -m brasileirao.export`)

Team ids are football-data.co.uk names (e.g. `"Flamengo RJ"`); display names come from `meta.json`.
Probabilities are numbers in 0–1; `probs` triples are `[home win, draw, away win]`.

| File | Content |
|---|---|
| `meta.json` | `season`, `data_through`, `generated_at`, `n_sims`, `models` (first = default), `games_played`, `games_remaining`, `zones` (`libertadores`, `relegation`), `teams` (`id → {name, short}`) |
| `table.json` | `rows[]`: `position, team, played, wins, draws, losses, goals_for, goals_against, goal_diff, points, form` (last 5, oldest first) |
| `predictions/<model>.json` | `teams[]`: `expected_points, expected_position, p_title, p_top6, p_relegation, positions` (P of each final position 1–20), `strength` (model-specific ratings) |
| `fixtures.json` | `fixtures[]`: `id` (index), `home`, `away`, `date` (Brasília time or `null`), `probs` per model |
| `score_matrices.json` | per Poisson-type model: one 11×11 grid per fixture, `P(home scores i, away scores j)` |
| `scorelines.json` | `H` / `D` / `A`: `[home goals, away goals, frequency]` of past scorelines with that result |
| `history/<model>.json` | `snapshots[]`: `date` (a Monday), `games` (season games before it), `teams → {p_title, p_top6, p_relegation, expected_points}` |
| `accuracy.json` | `leaderboard[]` (`id, name, log_loss, brier`), `calibration` (`model → [{bin, predicted, observed, n}]`), season ranges |

## Notes

- `output: "export"` makes the site fully static (no server code). `scripts/flatten-segments.mjs` runs after the
  build to copy route-prefetch files to the file names the client router requests, so prefetching works on any
  static host.
- `AGENTS.md` is generated by Next.js for coding assistants.
